2. Imagen de producción (docker build --target prod)
==============================================================================

  docker build --target prod -t shop-backend-test:prod .      -> OK, 483 MB
  El Dockerfile no copiaba static/ (256 imágenes del seed). Se añadió `COPY static ./static`
  y `ARG APP_VERSION=dev` (quita el aviso UndefinedVar).

  Se probó en una red aislada con un PostgreSQL 17 desechable (sin tocar el ShopDB del usuario).

  Sin DB_SSL y con STAGE=prod:
    ERROR [TypeOrmModule] Unable to connect to the database. Retrying (3)...
    Error: The server does not support SSL connections
  Causa: STAGE=prod activaba SSL siempre y el PostgreSQL de docker-compose.prod.yml no lo ofrece.
  Corrección: variable opcional DB_SSL (vacía = SSL solo con STAGE=prod, como antes);
  docker-compose.prod.yml la fija en false por defecto.

4. Limitaciones que esta validación dejó documentadas
==============================================================================

  - Las imágenes subidas en producción viven en el contenedor (/app/static/products); para
    conservarlas hay que montar un volumen.
  - Ambos compose usan container_name fijo y el puerto 5432: no pueden convivir con otro
    PostgreSQL ni entre sí en el mismo equipo.
  - Avisos de pnpm audit sin corrección compatible: deepmerge, glob y minimatch (Backend);
    zod, deepmerge y minimatch (Frontend, solo desarrollo).
