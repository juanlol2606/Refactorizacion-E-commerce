# Validación final - Semana 15 (rama refactor/semana-15)

Entorno: clon limpio de la rama en una carpeta temporal (commit c4f7e36), sin node_modules,
dist ni .env. Se siguieron los pasos del README raíz. Los secretos (JWT_SECRET, CSRF_SECRET y
contraseñas) se generaron al azar y no se muestran; el JWT y el token CSRF aparecen abreviados.

Diferencias con los valores por defecto del README, solo por convivir con servidores ya
abiertos en el equipo:

  - corepack enable --install-directory <carpeta temporal> en lugar de la instalación global.

## 5. Flujo en el navegador (http://localhost:5174 contra la API en :3000)
Secuencia de peticiones a la API registrada por el navegador:
 POST /api/auth/register            -> 201   (usuario nuevo, rol user; botón Admin ausente)
 POST /api/auth/logout              -> 200   (botones vuelven a "Login"; cookies expiradas)
 GET  /api/auth/check-status        -> 401   (sin sesión)
 POST /api/auth/login               -> 201   (test1@google.com; aparece el botón Admin)
 GET  /api/products?limit=9         -> 200   (catálogo con imágenes: GET /api/files/product/... -> 200)
 GET  /api/auth/check-status        -> 200   (tras recargar /admin/products la sesión persiste por cookie)
 POST /api/files/product            -> 201   (subida de una imagen PNG como admin, con X-CSRF-Token)
 POST /api/products                 -> 201   (producto "Producto de validacion final", con X-CSRF-Token)
 GET  /api/files/product/<id>.png   -> 200   (imagen recién subida)
 POST /api/auth/logout              -> 200
 GET  /api/auth/check-status        -> 401

Comprobaciones en el navegador:
 - document.cookie solo muestra csrf_token; access_token no es legible desde JavaScript (HttpOnly).
 - localStorage queda vacío (Object.keys(localStorage) -> []) durante todo el recorrido.
 - Producto guardado (GET /api/products/producto-de-validacion-final):
   {"id":"840301a1…","title":"Producto de validacion final","price":60,"stock":4,"sizes":["L"],
    "gender":"unisex","images":["8ee4f342…png"],"tieneUser":false}
   (la API ya no devuelve el propietario del producto).
 - Tras el logout, check-status responde 401 y los botones vuelven a "Login".
